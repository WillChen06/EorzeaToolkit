# iPhone Duo 任務 3：技能循環雙區版面

## 目標

依編輯器當下可用空間排列循環與技能選擇，resize 不打斷編輯內容與已完成的排序。

## 範圍

- 寬畫面循環在左、技能選擇在右；窄畫面上下排列。
- 兩區獨立捲動，循環標題、等級／分類選擇亦可隨各自區域捲動。
- 非 Accessibility 且本地寬度至少為 `2 × scaled 300pt + 1pt 分隔線` 時左右排列；300pt 隨 headline Dynamic Type 縮放。兩欄均分扣除分隔線的寬度。
- 上下排列時先扣除 1pt 分隔線，剩餘高度循環佔 40%、選擇佔 60%；高度不足 1pt 時分隔線縮為可用高度、內容高度為零。
- Accessibility 字級強制上下排列，文字允許換行。
- 空狀態改用不依賴方向的文案。

## 不在這個 Phase

不改首頁、列表詳情導覽、持久化格式或資料；不包含 roadmap 任務 4–8。保留既有新增、刪除、排序、清空與分類邏輯。保留已完成的排序，不保證 resize 當下正在進行的系統拖曳 session。

## 資料來源與狀態

沿用 SkillRotationViewModel、RotationSlot 與 SwiftData；等級／分類由編輯器持有，兩區維持同一套 view identity。參考 Xcode app-resizability skill，僅使用容器尺寸，不額外扣除 safe area。

## 驗收

- **AC-1** `[人工]` 編輯器可用寬度足夠時，循環在左、技能與等級／分類選擇在右；不足時循環在上、選擇在下。
- **AC-2** `[人工]` resize 前後保留職業、等級、分類、循環內容與已完成的排序；切換後仍可新增、刪除、拖曳排序與清空。
- **AC-3** `[人工]` 長循環和技能選擇都可捲動到最後一項，矮視窗不讓循環區擠走技能選擇。
- **AC-4** `[人工]` Accessibility 大字體改用上下排列，標題與操作不裁切，中英文皆可使用。
- **AC-5** `[自動]` 版面決策以本地可用寬度與字級判斷，測試涵蓋窄寬臨界值與 Accessibility 回退；上下模式循環高度依本地高度限制。
- **AC-6** `[diff]` resize 維持同一編輯器及子view identity，不重新建立VM或重設等級、分類、slot ID；不改持久化格式。
- **AC-7** `[diff]` 維持iOS17/Swift5.9、既有本地化與風格，不引入裝置型號/全域screen/orientation判斷。不含任務4-8與首頁變更。

驗證：專案生成、Simulator build、scripts/run_tests.sh；人工項須明確記錄通過或尚未驗證。
