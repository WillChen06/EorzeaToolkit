# AI Phase 1：用描述搜尋道具

## 目標

玩家可以用一句繁中描述找道具，例如「80級以上白魔能穿的頭部裝備」。App 把句子換成搜尋條件和名稱關鍵字，套用到現有的道具搜尋；套用後照常顯示在 filter 和搜尋列，可以接著調整。
描述搜尋只在 iOS 26 以上、裝置的 Apple Intelligence 可用時提供。
另外，搜尋列空白時也能只用 filter 列出道具，所有裝置都一樣。

## 範圍（這個 Phase 只做這些）

- 開工前用使用者另外寫的保留集量一次真實的準確度，達到門檻才做 App 的部分（見「保留集」）：
  - 評估工具新增保留集模式；
  - 結果記在 `docs/foundation-models-eval.md`。
- 道具搜尋畫面新增描述搜尋的按鈕和輸入句子的畫面（見「入口」「描述搜尋畫面」）。
- 依模型狀態顯示或隱藏按鈕，不可用時說明原因（見「模型狀態」）。
- 用 `prompts/item-query-eval.md` 的解析程式碼解析句子，解析結果套用到 filter 和搜尋文字（見「套用」）。
- 查配方的句子：有同名道具時直接打開它的 detail page（見「查配方」）。
- 道具搜尋：搜尋列空白、filter 有作用時，列出符合 filter 的道具。一般搜尋也一樣（見「只用 filter 搜尋」）。
- `AGENTS.md` 和 `scripts/run_item_query_eval.sh` 說明保留集模式。

## 不在這個 Phase

- 沒有模型時的描述搜尋（iOS 25 以下、不支援的裝置只用程式比對條件）。
- 模型出錯時改用程式比對到的條件。這個 Phase 一律當成失敗。
- 套用前預覽解析結果、套用後復原。
- 搜尋紀錄、範例清單、多輪對話（例：「再高一點的」）、語音輸入。
- 修改解析規則和給模型的指示，例如新增「坦克」「補師」這類叫法。保留集沒達標時另外改 spec。
- 道具說明文字、靠意思的查詢（例：能讓陸行鳥變色的東西）。
- 「X 能做什麼」（用材料反查）。
- 「都能用」的職業條件。filter 的職業條件是「任一職業能用」，「忍者跟武士都能穿」會列出其中一個職業能穿的。
- 手機上的延遲量測、Private Cloud Compute、tool calling。

## 保留集

- 使用者另外寫句子和預期結果，格式和 `Tools/ItemQueryEval/cases.json` 相同（包括 `group`）。
  - 至少 20 句，寫平常會打的說法，不必照 `item-query-eval.md`「評估集」一節的組成。
  - 實作者不參與撰寫，跑之前也不讀。
  - 放在 `Tools/ItemQueryEval/holdout.json`，跑完後連同結果一起 commit。
- 評估工具的保留集模式（`--holdout`）：
  - 沒指定 `--cases` 時讀 `Tools/ItemQueryEval/holdout.json`。
  - 檢查模式和正式評估都不檢查組成（各類別句數、總句數），也允許原文裡沒有的關鍵字，其他檢查照舊。
    預期結果寫使用者希望的搜尋，玩家的俗稱只能這樣表達（例：「爆發藥」指名稱有「寶藥」的道具）。模型只從原文擷取關鍵字，這種句子會算錯，量的就是俗稱的落差。
  - 門檻：用法 ≥ 90%、整句完全正確 ≥ 80%。保留集句數少，單一欄位的分母太小，各欄位正確率照樣輸出，只用來找原因。
  - 不用保留集模式時，行為和現在相同。
- 結果記在 `docs/foundation-models-eval.md`，和前幾輪同樣的格式。
- 沒達到門檻時，記錄原因，由使用者決定：
  - 調整解析規則或指示後重跑：要另外改 spec，而且調整過後這份保留集就不算保留集了；
  - 照現況做 App 的部分；
  - 停止這個功能。

## 模型狀態

依 `ItemQueryModelStatus`：

| 狀態 | 按鈕 | 描述搜尋畫面 |
| --- | --- | --- |
| 可用 | 顯示 | 可以搜尋 |
| Apple Intelligence 未開啟 | 顯示 | 說明要在「設定」開啟 Apple Intelligence，不能搜尋 |
| 模型未就緒（下載中） | 顯示 | 說明模型還沒準備好、稍後再試，不能搜尋 |
| 裝置不支援、不支援繁中、其他 | 不顯示 | — |
| iOS 25 以下 | 不顯示 | — |

- 進入道具搜尋畫面、打開描述搜尋畫面時重新判斷。
- 道具資料載入完成前，按鈕停用。

## 入口

- 道具搜尋畫面的 toolbar，filter 按鈕旁新增一個按鈕（✨ 圖示），VoiceOver 唸「用描述搜尋」。
- 點了從按鈕彈出描述搜尋畫面，和 filter 一樣：寬螢幕是 popover，窄螢幕是 sheet。

## 描述搜尋畫面

- 標題「用描述搜尋」，有「取消」和「搜尋」。
- 一個輸入框，打開時自動 focus。
  - 文字可以折成多行顯示，但不換行：鍵盤的搜尋鍵和「搜尋」按鈕都開始解析。
  - placeholder 是一個範例句子；輸入框下方一行說明可以寫什麼（職業、部位、等級、稀有度、HQ、能不能交易，或道具名稱的一部分）。
  - 再打開時，輸入框是上一次送出的句子。只存在記憶體，App 重開就清空。
- 輸入框空白、解析中、模型不可用時，「搜尋」停用。
- 模型可用時，打開這個畫面就預先載入模型，讓第一次解析快一點。
- 解析中：顯示進度，輸入框和「搜尋」停用。按「取消」或關掉畫面就放棄這次解析，結果回來也不套用。
- 解析完：

| 結果 | 畫面 |
| --- | --- |
| 可以套用（見「套用」「查配方」） | 關閉，套用 |
| 用法是「無法處理」 | 不關，顯示「這句話不像在找道具。描述用途或效果的查詢目前還不支援。」 |
| 查配方，但沒有關鍵字 | 同「無法處理」 |
| 搜尋，但沒有關鍵字也沒有任何條件 | 不關，顯示「沒有從這句話找到道具名稱或條件，請換個說法。」 |
| 出錯（被 guardrail 擋下、讀不到模型的回答、其他錯誤） | 不關，顯示「無法解析這句話，請換個說法，或直接用名稱搜尋。」 |

- 不關的時候句子保留，可以修改後再搜尋。

## 套用

- 解析用的道具資料和搜尋用的是同一份；遠端資料更新後用新的。
- 套用時整個取代原本的 filter 和搜尋文字，不和原本的合併。句子沒提到的條件回到預設值。

| 解析結果 | 套用到 |
| --- | --- |
| 關鍵字 | 搜尋文字；沒有關鍵字時清空 |
| 分類 | 分類 |
| 部位 | 裝備部位，包括「（無法裝備…）」的變體。filter 畫面會選取所有變體 |
| 職業 | 職業 |
| 裝備等級範圍 | 裝備等級 |
| 品級範圍 | 品級 |
| 稀有度 | 只選這些稀有度 |
| HQ 是／否 | 只要可 HQ／排除可 HQ |
| 可交易 是／否 | 只要可交易／排除可交易 |

## 查配方

- 用法是「查配方」、有關鍵字時，找名稱和關鍵字相同的道具，比較方式和名稱搜尋相同（不分大小寫）：
  - 恰好一個：filter 回到預設、搜尋文字是關鍵字，並打開那個道具的 detail page。那個道具沒有配方時一樣打開，detail page 會顯示其他取得方式。
  - 沒有或不只一個：照名稱搜尋關鍵字，filter 回到預設。

## 只用 filter 搜尋

- 搜尋列空白、filter 有作用時，列出符合 filter 的所有道具，排序和現在相同。
- 搜尋列空白、filter 沒作用時和現在一樣不列出，說明改成「輸入道具名稱，或設定篩選條件」。
- 搜尋列空白、filter 有作用但沒有結果時，說明是「請試著調整篩選條件」。

## 驗收

### 保留集

- **AC-1** `[人工]` 保留集模式的檢查模式，在句數或各類別句數少於「評估集」一節的組成時、關鍵字不在原文裡時不報錯；格式、名稱、範圍的錯誤照樣指出是哪一句，並以非 0 結束。
- **AC-2** `[人工]` 保留集模式的報告，門檻那一行依「保留集」一節的門檻判斷。
- **AC-3** `[人工]` 不用保留集模式時，`cases.json` 的檢查和報告跟現在相同，包括組成檢查。
- **AC-4** `[diff]` `docs/foundation-models-eval.md` 記錄保留集這一輪：環境、句數、各欄位和整句的正確率、失敗的句子、是否達到門檻，以及使用者的決定。
- **AC-5** `[diff]` `AGENTS.md` 和 `scripts/run_item_query_eval.sh` 說明保留集模式。

### 模型狀態與入口

- **AC-6** `[diff]` 描述搜尋用到 FoundationModels 的程式碼都在 iOS 26 的 availability 後面；iOS 25 以下不顯示按鈕。
- **AC-7** `[自動]` 每種模型狀態對到「模型狀態」一節的按鈕和描述搜尋畫面行為 —— 新增 unit test
- **AC-8** `[人工]` 模型可用的模擬器上，道具搜尋畫面有描述搜尋按鈕，VoiceOver 唸「用描述搜尋」。
- **AC-9** `[人工]` scheme 模擬「Apple Intelligence 未開啟」「模型未就緒」時，按鈕顯示，描述搜尋畫面說明原因、「搜尋」停用；模擬「裝置不支援」時沒有按鈕。

### 解析與套用

- **AC-10** `[自動]` 解析結果的每個欄位照「套用」一節對到 filter 和搜尋文字；句子沒提到的條件是預設值 —— 新增 unit test
- **AC-11** `[自動]` 套用整個取代原本的 filter 和搜尋文字 —— 新增 unit test
- **AC-12** `[自動]` 查配方時，恰好一個道具名稱和關鍵字相同就選取那個道具；沒有或不只一個時照名稱搜尋關鍵字。兩種情況 filter 都回到預設 —— 新增 unit test
- **AC-13** `[自動]` 無法處理、查配方沒有關鍵字、搜尋沒有關鍵字也沒有條件時，什麼都不套用，各自對到「描述搜尋畫面」一節的訊息 —— 新增 unit test
- **AC-14** `[自動]` 被 guardrail 擋下、讀不到模型的回答、其他錯誤時，什麼都不套用，顯示失敗訊息 —— 新增 unit test
- **AC-15** `[自動]` 放棄解析後才回來的結果不會套用 —— 新增 unit test
- **AC-16** `[人工]` 描述搜尋「80級以上白魔能穿的頭部裝備」：畫面關閉，搜尋列空白，filter 列反映條件，結果是白魔道士能穿、80 級以上的頭部裝備。
- **AC-17** `[人工]` 描述搜尋含道具名稱的句子（例：「白魔能穿的歐米茄身體裝備」）：搜尋列是關鍵字，結果符合條件。
- **AC-18** `[人工]` 描述搜尋查配方的句子，只有一個同名道具時打開它的 detail page。
- **AC-19** `[人工]` 解析中顯示進度，輸入框和「搜尋」停用。
- **AC-20** `[人工]` 無法處理或失敗時，畫面不關、句子保留、顯示訊息。
- **AC-21** `[人工]` 再打開描述搜尋畫面時，輸入框是上一次送出的句子。
- **AC-22** `[人工]` 鍵盤的搜尋鍵和「搜尋」按鈕都開始解析，輸入框不會換行。
- **AC-23** `[diff]` 模型可用時，打開描述搜尋畫面就預先載入模型。

### 只用 filter 搜尋

- **AC-24** `[自動]` 搜尋文字空白、filter 有作用時，列出符合 filter 的所有道具；filter 沒作用時不列出 —— 新增 unit test
- **AC-25** `[人工]` 搜尋列空白、filter 沒作用時，說明是「輸入道具名稱，或設定篩選條件」；filter 有作用但沒有結果時，說明是「請試著調整篩選條件」。

### 其他

- **AC-26** `[diff]` 新增和修改的使用者可見文字都走 `Localizable.xcstrings`，有英文和繁中。
