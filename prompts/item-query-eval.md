# Foundation Models：道具搜尋解析評估

## 目標

在 Mac 上用 Apple 的裝置端模型，量出「一句繁中描述 → 道具搜尋條件」解析得多準，結果用來決定要不要做 App 的描述搜尋。
評估工具留在 repo 裡，每次 iOS 大版本換模型時，用同一份評估集重跑。

## 範圍（這個 Phase 只做這些）

- 解析程式碼，App 之後直接用同一份：
  - 解析結果的結構（見「解析結果」）；
  - 給模型的指示，以及分類、部位、職業清單。清單從 `items.json` 和 App 的職業 filter 選項產生，不另外寫死一份。
    指示用完整的「句子 → 結果」範例說明，不放會被照抄的單一數值或名稱，範例也不取自評估集；
  - 把模型輸出的名稱對回 id 的邏輯。
- 解析程式碼放在 App 的原始碼目錄，App target 和評估工具 target 一起編譯。
  - 用到 FoundationModels 的部分全部放在 iOS 26／macOS 26 的 availability 後面。
  - App 這個 Phase 不呼叫它。
- `project.yml` 新增 macOS 命令列 target（評估工具），最低 macOS 26。CI 不 build、也不跑這個 target。
- 評估集 `Tools/ItemQueryEval/cases.json`，組成見「評估集」。
- `scripts/run_item_query_eval.sh`：build 評估工具並執行。另有檢查模式，不呼叫模型，只檢查評估集。
- 結果記錄在 `docs/foundation-models-eval.md`。
- `AGENTS.md` 的 Commands 加上評估工具。

前置條件：CI 改用 Xcode 27.1（#77）。解析程式碼由 App target 一起編譯，CI 需要有 FoundationModels 的 SDK。

## 不在這個 Phase

- App 的描述搜尋入口、prewarm、各種狀態畫面，以及把解析結果套用到搜尋（AI Phase 1）。
- 道具說明文字、靠意思的查詢（例：能讓陸行鳥變色的東西）。
- Private Cloud Compute、tool calling、多輪對話。
- 手機上的延遲，只有實機量得準。
- 修改 filter 本身，裝備等級由 `prompts/item-equip-level.md` 處理。

## 解析結果

每句話解析成下列欄位，沒提到的欄位留空。

除了用法和關鍵字，模型填的每個條件都要附上它在原文裡的依據（原文中連續的一段字）。解析時：
- 依據不在原文裡的條件丟掉（比對時不分大小寫、忽略空白）；
- 等級範圍的上限或下限，數字沒出現在依據裡的那一端視為沒填；
- 關鍵字本身不在原文裡就丟掉。

- **用法**：搜尋／查配方／無法處理。
  - 搜尋：用條件或名稱找道具。
  - 查配方：「做 X 要什麼材料」「X 怎麼做」。
  - 無法處理：描述用途或效果的查詢、跟道具無關的句子。
- **關鍵字**：道具名稱的一部分。只能從原文擷取，不補全、不翻譯、不改寫。查配方時就是那個道具的名稱。
  跟分類、部位或職業的名稱相同的關鍵字丟掉（例：「頭部」「暗騎」）。
- **分類**：從 `items.json` 的 112 個分類名稱中選，可多選。用於武器、工具的種類（例：雙手幻杖）、盾、靈魂水晶，以及非裝備道具（例：藥品、食材）。
- **部位**：主手、副手、頭部、身體、手部、腿部、腳部、耳部、頸部、腕部、戒指，共 11 個，可多選。
  - 防具和飾品的分類，解析時換成對應的部位（例：「頭部防具」→ 頭部、「耳飾」→ 耳部）。
    換的是「可裝備的道具全部裝在同一個部位，而且不是主手或副手」的分類，從 `items.json` 算出；
    盾、武器、工具的分類維持分類。
  - 盾用分類「盾」，不用部位「副手」；靈魂水晶用分類，不算部位。
  - 部位是 `items.json` 裝備部位名稱中不含「（」的那些，扣掉靈魂水晶。
  - 對回 id 時，包含「（無法裝備…）」的變體。例如「身體」包含「身體（無法裝備頭部）」等 6 種。
- **職業**：App 職業 filter 的 32 個縮寫。玩家的叫法都要對到同一個縮寫：
  - 官方名稱：讀 `items.json` 中只含單一職業的職業分類（例：白魔道士）；
  - 常用簡稱：寫在以縮寫為 key 的別名表（例：白魔、WHM），key 只能是 App 職業 filter 的縮寫；
  - 不收 App filter 上顯示的名稱（例：白魔法師）；
  - 整個名稱比對，不做部分比對，「騎士」不會對到「龍騎士」。
- **裝備等級範圍**：「80 級」= 80–80，「80 級以上」= 80–100，「80 級以下」= 1–80。
- **品級範圍**：只在有說「品級」「iLv」「裝等」時才填。沒說的「X 級」一律視為裝備等級。「品級 X 以上」= X–795（App filter 的上限）。
- **稀有度**：固定 5 個值：1 一般（白）、2 稀有（綠）、3 貴重（藍）、4 武勳（紫）、7 紅蓮（粉）。
- **HQ、可交易**：例如「可以 HQ」= 只要可 HQ，「不能交易」= 只要不可交易。

## 評估集

- 每句包含編號、所屬類別、原文和預期的解析結果。
- 至少 41 句（下列組成加總），組成：
  - 組合條件（兩個以上條件）20 句；
  - 裝備等級 5 句、品級 3 句；
  - 查配方 5 句；
  - 名稱裡有可能被 guardrail 擋下字眼的道具 5 句（例：刀、死、血），用 `items.json` 裡真的有的道具；
  - 無法處理 3 句；
  - 職業用簡稱或別名，散在上面各類裡。
- 初稿由實作者寫，使用者確認後定稿。

## 評估工具

- 輸入：`items.json` 和評估集。
- 每句用新的 session，取樣固定，同樣的輸入得到同樣的輸出。
- 輸出：
  - 用法、各欄位的正確率，以及整句完全正確的比例；
  - 錯誤清單：每句的預期與實際；
  - 被 guardrail 擋下和其他錯誤分開計數，各自列出是哪幾句；
  - 平均耗時，只供參考，Mac 的速度不代表手機；
  - 環境：macOS 版本、日期。
- 模型不可用時（Apple Intelligence 未開啟、模型未下載、裝置不支援、不支援繁中），說明原因並以非 0 結束。
- 評估跑完就以 0 結束，包括有句子被擋或出錯時。只有模型不可用、輸入檔案有誤時以非 0 結束。
- 正確率的算法：
  - 比對前先把名稱對回 id 或縮寫，多選欄位不計順序；
  - 每個欄位只算「預期或實際有值」的句子，兩邊都空的不算進去；
  - 被 guardrail 擋下或出錯的句子，在預期有值的欄位都算錯（用法每句都有值，所以一定算進去）；
  - 整句完全正確的比例以全部句子為分母。
- 檢查模式檢查：
  - 每句的格式，以及編號不重複；
  - 用法是三種之一；
  - 分類、部位、職業都是清單裡的名稱或縮寫；
  - 範圍的下限不大於上限，且在 1–100（裝備等級）、1–795（品級）之內；
  - 關鍵字出現在原文裡。
  - 有錯時指出句子的編號和原文。

## 繼續做 App 的門檻

用法 ≥ 90%、關鍵字 ≥ 90%、其他欄位各 ≥ 85%。
沒達標時，在結果文件記錄原因，由使用者決定調整後重跑，或停止這個功能。

## 驗收

- **AC-1** `[diff]` `project.yml` 新增 macOS 命令列 target，最低 macOS 26；它和 App target 編譯同一份解析程式碼檔案，沒有複製。
- **AC-2** `[diff]` 解析程式碼中用到 FoundationModels 的部分，都在 iOS 26／macOS 26 的 availability 後面。
- **AC-3** `[自動]` CI 的 build 與 unit test 通過，App target 包含解析程式碼 —— CI
- **AC-4** `[自動]` 部位對回 id 時包含全部變體 —— 新增 unit test
- **AC-5** `[自動]` 職業的不同叫法對到同一個縮寫 —— 新增 unit test
- **AC-6** `[自動]` 清單裡不存在的分類、部位、職業名稱被忽略，不會讓解析失敗 —— 新增 unit test
- **AC-7** `[人工]` 評估集的格式錯誤，或預期結果用了不存在的名稱時，檢查模式會指出是哪一句，並以非 0 結束。
- **AC-8** `[人工]` 評估集符合「評估集」一節的組成，內容經使用者確認。
- **AC-9** `[人工]` 模型不可用時，工具說明原因並以非 0 結束，不輸出分數。可以用 Xcode scheme 模擬 Foundation Models 不可用的狀態。
- **AC-10** `[人工]` 跑完後輸出「評估工具」一節列的每一項。
- **AC-11** `[人工]` 同一份評估集連跑兩次，每句的解析結果相同。
- **AC-12** `[人工]` 被 guardrail 擋下的句子分開計數，工具不會中止。如果這次沒有任何句子被擋，在結果文件註明。
- **AC-13** `[diff]` `docs/foundation-models-eval.md` 記錄這次的環境、各欄位正確率、失敗的句子，以及是否達到門檻。
- **AC-14** `[diff]` `AGENTS.md` 說明評估工具怎麼執行，並註明 CI 不跑。
- **AC-15** `[自動]` 給模型的分類、部位、職業清單由道具資料和 App 的職業清單產生：資料多一個分類或部位時，清單跟著多 —— 新增 unit test
- **AC-16** `[自動]` 依據不在原文裡的條件被丟掉；等級範圍中數字不在依據裡的那一端視為沒填；不在原文裡的關鍵字被丟掉 —— 新增 unit test
- **AC-17** `[自動]` 防具和飾品的分類換成對應的部位，盾、武器、工具的分類維持不變 —— 新增 unit test
- **AC-18** `[自動]` 跟分類、部位或職業名稱相同的關鍵字被丟掉 —— 新增 unit test
